# bottom-radius-test —— 屏幕底部遮挡 & 圆角半径实测

用一块**铺满整屏的 canvas** 去"量"屏幕：底部哪些位置没被遮挡、屏幕圆角到底切掉了多少、
该按多大的半径（R 角 / dp）来做 UI。全部结论都带证据，测不到就报"测不到"，不猜。

打开方式：`index.html`（需用手机浏览器访问，二维码见下方"怎么在手机上打开"）。

---

## 一、先说清楚一个物理限制（这决定了整套方案）

网页 JS **读不到系统合成器输出的画面**。`canvas.getImageData()` 读到的永远是自己"画进去"
的那份备份缓存，不是屏幕上真实的像素；`html2canvas` 之类也只是重绘页面 DOM。
所以"屏幕上哪些位置被遮挡"不可能在页面里直接量出来，只能靠三类可观测信号：

| 信号 | 能回答什么 | 局限 |
| --- | --- | --- |
| ① 视口几何<br>`visualViewport` / `innerHeight` / `screen` / `env(safe-area-inset-*)` | 浏览器 UI、状态栏、手势条占了多少高度 | 只给高度，给不出"哪些 x 位置被挡" |
| ② 命中测试<br>`document.elementFromPoint(x, y)` | 某点在不在视口内、命中的是 canvas 还是别人的 UI | 只给"是/否"，且受 DOM 覆盖关系影响 |
| ③ **截图回读**（本工具的核心） | 逐像素：这个位置到底显示了 canvas 还是别人的 UI | 需要用户截一张整屏图并贴回来 |

## 二、核心做法：把屏幕坐标编码成"绝对位置条码"

`ruler.js` 在整屏 canvas 上绘制一张**绝对位置条码**：

- 每 **2 CSS px** 一个色块，色块序号先做 12bit **格雷编码**，再按 4bit/通道摊到 RGB；
  相邻色块只差一个通道（步进 15），因此对缩放、轻微色偏、JPEG 噪声都有冗余。
- 颜色整体抬到 **30–255**：系统 UI 常常是纯黑（暗色模式 / 刘海 / 工具栏），
  若编码里存在接近纯黑的色块，黑色遮挡会被误判成"可见"。
- **纯条码区**（绝不允许任何装饰覆盖）：四边 12px 边缘条（左右条编码 y、上下条编码 x）
  - 四角 z×z 探针方块（编码 x）。
- **装饰区**：只在中部十字区域放信息卡、网格、标签，并严格裁剪。
- 两把**梳齿标定尺**（白色细线，间距恒为 10 CSS px）：解码端据此在
  **完全不知道缩放比例**的情况下算出"截图 → CSS px"的映射（对 0.2x 到 3x、非等比、
  带色偏的截图都成立）。

把截图贴回来后，逐点解码：

```
能解码  → 该位置的 canvas 像素确实显示在了屏幕上
解不了  → 被系统 / 浏览器 UI 盖住，或落在屏幕圆角之外
反解坐标 ≈ 采样坐标（校验）→ 防止把别的色块误认成这个位置
```

于是得到**逐像素的可见区边界**，再用最小值拟合圆角圆弧：

```
被切掉的水平深度  x(y) = R − √(R² − (y − yt)²)
  · atScreenBottom ：yt = H − R —— 弧顶在屏幕底边 → 这是屏幕的物理圆角（最可信）
  · atVisibleBottom：yt = 可见底边 − R → 是浏览器工具条自身的圆角
  · free           ：R 与 yt 都自由 → 用来发现"这段弧长在某个遮挡物上"
```

几个关键工程细节（都是被自检抓出来的坑）：

- **边界必须从 x=0 起扫**：小半径（平板 R≈18）的浅切弧线只有 1–2px 深，从 12px 处起扫会全部丢掉。
- **底部扫描必须延伸到 yBot 以下**：遮挡物自带圆角时，能看见的像素恰好在 yBot 之下的凹口里。
- **量不到也是结论**：底部遮挡 ≥ 圆角半径时，屏幕圆角整段被压在 UI 之下 → 如实报"测不到"，
  此时用顶部圆角（同机同值）给出建议值。
- **区间残差**：边界是量化到整数像素的（真实割深落在 `(x−1, x]`），用点残差会把半径系统性抬高几像素。
- **模型选择（奥卡姆剃刀）**：几十像素长的短弧存在"半径大+弧顶低"与"半径小+弧顶高"的等价解，
  残差接近时优先采用自由度更少、物理上更合理的模型。
- **拟合不能忽略弧外的点**：否则小半径模型可以整段丢弃数据、零残差地"解释"它盖不住的弧。
- **标定必须分轴**：左右边缘条编码 y（只能校 sy）、上下条编码 x（只能校 sx）；混在一起打分会漂移。

## 三、怎么用（手机上）

1. 手机浏览器打开本页（下面有二维码）。
2. 先看"免截图自动探测"：屏幕尺寸、dpr、`visualViewport`、安全区、底部被浏览器 UI
   占用的估算高度、`elementFromPoint` 能命中的最靠下位置 —— 这些不需要截图。
3. 点 **"隐藏面板，准备截图"**：整屏只剩探针条码，不要再滚动页面。
4. 用系统截屏（必须是**整屏**，不要裁剪；QQ 内置浏览器底部干净时效果最好）。
5. 回到页面，把截图**粘进虚线框**（长按 → 粘贴）或点框选文件。
6. 读结论卡与"可见性重建"图；需要原始数据就复制结果 JSON。

> 若"屏幕尺寸"显示明显不对，用页面里的 **手动校准** 填入正确的 CSS 尺寸再重绘探针。

## 四、怎么读结果

- **屏幕圆角半径（dp）**：结论卡里的大数字。1 CSS px = 1 dp（Android）/ 1 pt（iOS），
  可直接用于 `--radius` 之类的设计变量。
- **底部完全被遮的高度**：该高度内没有任何 canvas 像素（浏览器工具栏 / 系统手势条）。
- **整行可见的安全区 y 范围**：可以直接摆放 UI、不必担心被切掉的范围。
- **四角拟合表**：每个角的 R、采用的模型、弧顶位置、残差、边界点数，以及并列解。
- **"遮挡物圆角"**：单独列出，是工具条 / 面板自己的圆角，**不是**屏幕半径，别混用。
- **警告**：例如「截图被裁剪过」——这时底部与圆角结论不可信，工具会明说。

精度与边界情况：圆角半径在整屏高清截图下误差约 ±1–2 CSS px；截图会被等比缩放过也照样能解
（梳齿标定）；被 UI 压住的圆角就是测不到，这是物理限制，不是算法问题。

| `index.html` | 页面（探针 + 操作面板 + 报告） |
